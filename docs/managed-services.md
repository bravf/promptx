# MCP 运行任务

卡片默认展示运行中和未忽略的失败任务，正常结束或主动停止的记录收进默认折叠的“已结束”。失败可忽略后归入已结束，支持清空已结束（移除卡片和缓存日志，不停止任何运行进程）。相同会话、目录和命令再次启动后替换旧的已结束记录。

`url` 用于页面主入口，`healthUrl` 仅用于就绪探测。自动发现优先取首个非 API/健康接口地址；仅发现健康接口时不生成页面入口，不自动删掉子路径推测根页面。显式传入健康接口作为 url 时将其转为探针。

远程部署、上传、通过 SSH 执行 systemctl/Docker 启停等有限命令使用普通命令工具，结果保留在 Timeline，不创建运行任务卡片。只有需持续维持的 SSH 隧道、端口转发、SSH 前台程序使用 `type=remote`（远程连接），不进行 URL 发现和 HTTP 探测。运行状态只表示本机连接进程存活，不代表远程服务健康；停止连接不保证远程程序退出。旧任务保留原类型和日志，不根据命令含 ssh 自动隐藏。

运行任务按 `type` 区分 `web`（Web 服务）、`desktop`（桌面应用）、`watch`（监听任务）和 `process`（通用进程）。仅 Web 服务显示地址和 HTTP 就绪状态；其他类型显示进程是否运行。桌面应用须直接以前台方式执行 `.app/Contents/MacOS/` 中的实际程序，不能通过 `open` 启动后脱离托管；运行中只代表进程存活，不保证窗口已经显示。

启动和重启均不自动打开终端，点击“查看日志”才打开。失败时卡片显示末尾日志摘要。工具名称和接口路径保持兼容；未提供类型时，有 URL 的按 Web 服务处理，Mac 应用可执行路径按桌面应用处理，其余按通用进程处理。通用进程启动检查期间若日志出现本机 URL，自动升级为 Web 服务。

Agent 启动的开发服务器、预览服务及监听进程由 PromptX Daemon 的独立终端托管。Agent 回复完成、释放会话或退出 MCP 客户端后，服务继续运行；关闭前端终端标签也不会停止服务。

## 使用

向会话发送：“请用 PromptX 终端启动这个项目的开发服务，并验证地址可访问。”

宽屏 Timeline 内容区右上角悬浮显示“运行任务”卡片，支持查看日志、停止和重新启动。卡片独立于消息滚动，不占布局空间，消息区保持原有宽度和高度；可折叠卡片查看其下方内容。窄分栏和手机显示可展开的紧凑悬浮卡片。切换会话或刷新页面后，运行状态通过现有 SSE 连接恢复。

本机开发地址只代表电脑上的服务。手机 Relay 不能通过手机的 `localhost` 访问电脑开发端口，卡片会提示使用可访问的局域网地址或部署地址。

## 工具

| MCP 工具 | 用途 |
| --- | --- |
| `start_service` | 在工作区内指定目录执行前台命令，返回终端 ID、就绪状态和有界日志 |
| `list_services` | 查看当前会话服务 |
| `read_service_logs` | 根据游标读取日志，单次最多返回末尾 12,000 字符 |
| `stop_service` | 停止服务及其进程组，保留终端日志 |
| `restart_service` | 重启已停止服务，返回新终端 ID |

同一会话中相同目录、相同命令的运行中服务会复用。工作目录须位于当前工作区内。可指定本机 HTTP(S) 地址作为就绪探针，也可从启动日志识别地址；仅进程仍运行且地址返回成功状态时才报告 `ready`。未能验证的运行中进程报告 `unverified`，不能据此声称页面已可访问。

Codex、Claude、Grok、Kimi 都由各自 Provider 注入 MCP 配置，不修改用户全局 CLI 配置。桥接监听随机 loopback 端口，令牌只允许操作对应会话，Runtime 关闭后撤销，不下发前端或 Relay。日志留在本机终端缓存，最大 256 KiB，前端继续使用现有终端接口。

## 生命周期与限制

服务依赖 PromptX Daemon 存续。Daemon 重启或退出会停止所有托管服务；本版没有后台守护、崩溃自动恢复或开机自启。归档会话、工作区不可用或改变执行目录会清理关联终端。有限的构建、测试命令仍通过 Agent 原有工具执行。

就绪检查发生于启动时，后续卡片依据进程状态更新，不持续探测 HTTP 健康状态。停止服务后须等待进程退出才能重启。

## 验证

自动测试覆盖真实 MCP stdio/PTY、并发启动复用、权限隔离、目录逃逸、端口冲突、退出清理以及桌面和手机加密 Relay 的查看、停止、重启流程。

实际模型验证：Codex、Grok、Claude 均能调用 MCP 启动 HTTP 服务，Runtime 退出后地址仍可访问。Kimi 的新建及恢复配置通过 ACP 模拟验证；当前账号订阅返回 403，尚未完成 Kimi 实际模型调用验证。
