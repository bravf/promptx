# 会话终端

点击 Timeline 顶部的终端图标，在面板底部打开终端。每个会话可创建多个独立 Shell；新终端始终从会话的真实执行目录启动，Worktree 会话进入对应的 Worktree，不继承其他终端的 cd 目录。

- 点击标签栏的 ＋ 新建终端，点击标签切换。
- 双击标签或点击铅笔图标重命名，名称保存在 Daemon 的终端记录中。
- 标签的 × 会结束并移除该终端；区域右侧的 × 仅收起界面，所有进程继续运行。
- 进程自行退出后，标签显示“已退出”，可点击重新启动并保留原名称。
- 拖动上沿调整高度，或点击放大按钮填满当前面板。
- 选择文本后使用 Ctrl+C / Command+C 复制；没有选择文本时 Ctrl+C 发送中断。
- 切换会话、收起和刷新不结束进程；再次打开恢复列表、名称和上次选中的标签。
- 会话归档、删除或绑定目录变化后，后台清理其所有终端。Daemon 重启后不恢复终端列表与进程。

## 资源与传输

前端使用 xterm.js，Daemon 使用 node-pty。终端资源按需加载，每个打开的面板只挂载一个终端模拟器；切走的标签不渲染，也不拉取输出。整个区域收起、被文件抽屉覆盖或浏览器标签页进入后台时停止输出请求。

输出与输入通过现有 API 传输，远程使用现有 E2EE Relay，不另开公网端口。活跃输出约每 100ms 拉取，空闲逐渐降至每 1500ms；输入会唤醒快速拉取。可见面板每 5 秒同步一次轻量终端列表。输入合并短时间内的字符，尺寸调整做防抖。

每个终端最多保留约 256K 字符的原始输出历史，短输出合并为分块，防止大量小对象占用内存；较早记录会截断，不写入数据库或日志。切换标签时重放近期历史，并非完整终端屏幕快照。后台 Shell 内实际运行的程序仍会占用自己的 CPU 和内存。

实现参考了本地 Paseo 的独立终端 ID、列表与输出分离、输出合并和尺寸防抖思路；PromptX 保留现有 API / Relay 传输方式，没有引入其 Worker 与二进制流架构。

## 平台

安装依赖时需要允许 node-pty 的原生构建脚本，仓库已配置 pnpm onlyBuiltDependencies。没有预编译包的平台可能需要本机 C/C++ 编译工具。macOS 已完成真实 PTY 验证，Windows ConPTY 和 Linux 仍需在对应系统实测。
