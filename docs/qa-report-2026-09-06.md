## 缺陷清单

### D1 / P1：自定义端口的生产页面无法新建会话

- 位置：`apps/daemon/src/security/corsPolicy.js:33`；`apps/daemon/src/app.js:23`。
- 复现：设置 `PORT=3181` 启动 Daemon，不额外配置该端口的 `PROMPTX_ALLOWED_ORIGINS`；打开 Daemon 托管的 `http://127.0.0.1:3181`，输入有效目录并点击“创建会话”。
- 实际：浏览器发出的 `POST /api/v2/projects` 返回 `403 origin_not_allowed`，无法创建会话。页面和健康检查能正常加载。
- 预期：配置了监听端口后，合法的本地同源页面能够执行正常 API 写操作。
- 原因：默认 Origin 白名单只包含固定端口，未根据实际服务端口补入同源地址。E2E 显式传入 `allowedOrigins: [baseUrl]`，所以没有覆盖默认启动配置。
- 证据：`scripts/qa/dev-smoke.test.mjs` 第二条测试；`tmp/qa-20260906/promptx-qa-20260906-custom-port.log`。
- 临时办法：显式设置 `PROMPTX_ALLOWED_ORIGINS=http://127.0.0.1:3181`。本轮未修改配置来掩盖该缺陷。

### D2 / P2：当前目录会话无法推送有效的跟踪分支

- 位置：`apps/daemon/src/api/routes.js:116`、`:313`。
- 复现：临时 Git 仓库有 `main` 分支和本地 bare `origin`，已建立 upstream；创建 `executionKind=local` 会话，修改文件并通过 commit API 提交，再调用 push API。
- 实际：提交成功，推送返回 `409 {"error":"branch_required"}`，远端未更新。
- 预期：从执行目录解析有效分支后推送；若产品明确仅允许 Worktree 推送，应在协议和能力中表达限制。
- 原因：当前目录会话的环境 `branchName` 被写为空串，push 只读取此字段，不读取真实 Git 分支。
- 证据：`QA-GIT-02`。该能力当前主要暴露于 API 和前端 API 封装，主界面尚未提供推送按钮。

### D3 / P2：源 Worktree 有未提交修改仍被标记合并成功并归档

- 位置：`apps/daemon/src/api/routes.js:320`。
- 复现：创建 Worktree 会话，修改 `note.txt` 但不提交；保持目标 `main` 工作区干净，调用 merge API。
- 实际：返回 `200 merged=true`，会话变为 `archived`；未提交修改没有进入目标分支。
- 预期：阻止该交付操作并提示先提交，至少不能将未完成的工作默认归档。
- 原因：只检查目标工作区是否干净，没有检查源 Worktree 的未提交内容。
- 证据：`QA-GIT-03`。修改仍留在源 Worktree，本轮未观察到文件被删除；风险是成功状态误导和会话从活动列表消失。

### D4 / P2：普通文件可被保存为会话执行目录

- 位置：`apps/daemon/src/api/routes.js:108`、`:370`。
- 复现 A：调用 `environment/rebind`，传入仓库内已有普通文件 `note.txt` 的绝对路径。
- 复现 B：创建 `executionKind=existing` 会话，`cwd` 同样传入该文件路径。
- 实际：分别返回 200 和 201；数据库保存文件路径作为 `cwd`，环境状态仍是 `ready`。
- 预期：返回 400，重绑失败时保留原有目录，创建失败时不新增不可用环境。
- 原因：只调用 `realpathSync` 判断路径存在，没有检查 `isDirectory()`。
- 证据：`QA-INPUT-03`、`QA-INPUT-04`。

### D5 / P2：部分非法输入被错误归类为服务端故障

| 输入 | 实际响应 | 预期 |
| --- | --- | --- |
| 新建 Worktree，`slug=../escape` | 500 `internal_error`，中文名称错误 | 400；不创建记录 |
| 新建会话，未知 `providerId` | 500 `internal_error` | 400 或明确的客户端错误 |
| 更新工作区，`displayName={}` | 500，`Too few parameter values were provided` | 400 参数类型错误 |

- 位置：`apps/daemon/src/environments/worktreeService.js:22`，`apps/daemon/src/api/routes.js:166`，`apps/daemon/src/agent/providerRegistry.js`。
- 证据：`QA-INPUT-01`、`QA-INPUT-02`、`QA-INPUT-05`。
- 影响：输入错误进入服务故障路径，部分响应直接暴露英文数据库底层异常。

### D6 / P2：目录建议浮层遮挡新建会话的错误提示

- 位置：`apps/web/src/views/WorkbenchView.vue:948`、`:1355`；`apps/web/src/components/DirectorySearchInput.vue`。
- 复现：输入一个有效目录，保持目录建议浮层打开，直接点击“创建会话”并触发 API 失败；D1 可提供真实的失败场景。
- 实际：错误提示已渲染在路径输入框下方，但被目录建议覆盖，截图中看不到错误原因。
- 预期：提交时关闭目录建议，或确保错误提示不会被建议层遮挡。
- 证据：`dev-smoke.test.mjs` 输出 `errorText=该网页来源不能访问 PromptX Daemon。`、`covered=true`；`document.elementFromPoint` 命中目录建议的路径文字，而非错误提示。
- 截图：`tmp/qa-20260906/screenshots/production-custom-port.png`。
- 测试启示：Playwright 的文本 `waitFor()` 不等价于“元素没有被其他元素遮挡”。

### T1 / P3：现有 Worktree 单测在真实仓库留下分支与目录

- 位置：`apps/daemon/src/app.test.js:285`。
- 原因：该测试把 `process.cwd()` 作为工作区，创建第二个 Worktree 后只删除第一个会话，结束时只关闭 App。
- 本轮证据：新增 `codex/test-1788669159728` 分支和隔离目录下对应 Worktree；测试结束后仍出现在真实仓库 `git worktree list` 中。
- 建议：使用临时 Git 仓库，并在 `t.after` 中清理 Worktree 和分支。
- 处理：本轮创建的 Worktree 已确认干净后移除，对应分支使用 `git branch -d` 删除；已有工作区和分支未清理。
